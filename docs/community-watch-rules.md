# 馬特市守望相助隊規章

版本：v0.1 試行草案

本規章用於「馬特市守望相助隊」第一階段試行。目標是讓少數受託市民協助移除明確垃圾留言，同時用公開留痕、站方覆核與申訴管道防止濫權。

## 基本原則

- 權限要小：隊員只能處理留言，不能刪文章、動態本文、帳號，也不能停權或關小黑屋。
- 範圍要窄：第一版只處理明確垃圾留言，理由只有「色情廣告」與「濫發廣告」。
- 不做重審批：隊員可以直接處理明確垃圾留言；防弊靠公開紀錄、站方覆核、申訴與停權。
- 所有操作公開留痕：誰在什麼時間、因為什麼理由處理了哪則留言，都要能在公開紀錄頁查到。
- 站方保留最終決策權：站方可以覆核、恢復留言、調整理由、停用隊員資格。
- 不讓公開頁變成垃圾內容展示牆：原留言內容預設毛玻璃遮蔽，點開才可閱讀。
- AI 不直接刪除留言：第一階段 AI 只可作為候選檢測或提示，不得自動移除留言。

## 隊員身份

守望相助隊員是由站方指定的受託使用者，不是一般使用者預設權限，也不是站方員工身份。

公開頁顯示隊員在 Matters 站上自己取的顯示名稱。系統內部可以保留必要的 user ID 作為稽核資料，但公開頁不顯示內部 ID、email、IP 或其他個資。

## 加入資格

候選人應符合以下條件：

- 是 Matters 使用者，帳號狀態正常。
- 理解守望相助隊只處理留言垃圾廣告，不處理立場、觀點、爭議或人際衝突。
- 願意接受所有處理紀錄公開。
- 願意被站方覆核，且接受誤判時恢復留言或停用資格。
- 願意用自己的 Matters 顯示名稱出現在公開紀錄中。

第一階段建議採邀請制或少量開放申請，由 admin 手動指定 `communityWatch` 權限。不要在 MVP 建大型報名、投票或多層審核流程。

## 加入流程

1. 站方確認候選人理解本規章。
2. 站方確認候選人知道處理紀錄會公開。
3. admin 在現有後台或管理工具中指定該帳號的 `communityWatch` 權限。
4. 候選人重新登入或重新整理後，才會在留言選單看到守望相助隊操作。
5. 站方可先安排一至兩則 staging 測試留言，確認候選人理解操作邊界。

## 任期與試行期

第一版建議採「試行期 + 固定任期」：

- 試行期：第一次加入後 30 天。
- 正式任期：試行期通過後，每期 3 個月。
- 續任：任期結束前由站方簡單確認是否續任，不需要複雜審批。
- 人數：第一階段維持少數隊員，建議先控制在 5 到 20 人以內。

試行期與任期不是硬性績效考核，也不設最低刪除數量。守望相助隊不是要鼓勵多刪，而是讓明確垃圾留言能被快速處理。

## 資格維持

隊員維持資格需要符合以下條件：

- 只處理明確垃圾留言。
- 只使用兩個第一版理由：「色情廣告」、「濫發廣告」。
- 不把功能用於立場分歧、批評、冒犯感、私人爭執或不喜歡的正常留言。
- 不處理自己無法判斷的邊界案例；不確定時留給站方或不處理。
- 不公開轉貼被移除留言中的垃圾連結、色情內容、詐騙內容或個資。
- 不使用自動化工具大量操作。
- 願意配合站方覆核、說明與停權決定。

站方可以定期抽查處理紀錄。抽查重點不是刪除數量，而是理由是否合理、是否越權、是否有重複誤判。

## 處理準則

隊員可以移除的留言：

- 明確色情廣告。
- 明確濫發廣告。
- 多處重複張貼的推銷、詐騙、導流或外部聯絡廣告。
- 和原討論無關、主要目的明顯是廣告或導流的留言。

隊員不應移除的留言：

- 政治立場、社會議題、價值觀不同的留言。
- 批評作者、批評平台、語氣尖銳但仍屬討論的留言。
- 內容低品質、離題但不明顯是垃圾廣告的留言。
- 需要脈絡判斷的爭議留言。
- 文章、動態本文、帳號、個人頁、頻道、圈子內容。
- circle 相關留言；circle 要落日，不納入本專案。

若留言同時包含垃圾廣告與其他內容，以垃圾廣告為主判斷；若看不出明確廣告目的，不要使用守望相助隊權限。

## 利益衝突與自我約束

隊員可以處理自己文章或動態下的明確垃圾留言，但不得用守望相助隊權限處理與自己發生爭執的正常留言。

若留言涉及隊員本人、人際衝突、長期爭議、檢舉對象是隊員熟人或對立方，建議交由站方處理。

## 退出

隊員可以隨時退出。退出方式：

- 通知站方或指定窗口。
- admin 移除該帳號的 `communityWatch` 權限。
- 權限移除後，隊員不再看到處理入口，也不能呼叫移除留言 API。

退出不會刪除過去公開 audit log。過去紀錄仍保留作為公開稽核資料，但如涉及有效個資請求，站方可以清除原留言內容。

## 停用與暫停資格

站方可以在以下情況暫停或取消隊員資格：

- 超出權限範圍。
- 多次誤刪正常留言。
- 處理與自己衝突相關的留言。
- 嘗試繞過公開留痕。
- 轉貼或擴散垃圾內容、色情內容、詐騙連結或個資。
- 拒絕配合站方覆核。
- 帳號本身出現安全風險或違規行為。
- 長期未登入或無法聯絡，站方認為需要清理權限。

停用不需要多層審批。為了保護社群與避免風險，站方可以先停用，再視情況說明或恢復。

## 申訴與覆核

被移除留言的使用者可以寄信到 `hi@matters.town` 申訴，並附上留言 ID 或公開紀錄連結。

站方覆核後可以：

- 維持原處理。
- 恢復留言。
- 調整理由。
- 標記申訴狀態。
- 清除原留言內容但保留 audit metadata。
- 暫停或取消隊員資格。

所有站方覆核操作也應留痕。

## 公開紀錄

每次隊員處理留言都應產生公開紀錄，至少包含：

- 公開紀錄 ID。
- 留言 ID。
- 來源類型。
- 來源標題或來源 ID。
- 移除理由。
- 隊員顯示名稱。
- 處理時間。
- 申訴狀態。
- 站方覆核狀態。

公開頁原留言內容預設毛玻璃遮蔽。使用者可點開全文，但頁面應提醒內容僅供申訴、覆核與社群稽核使用，不鼓勵轉貼。

## 資料與隱私

守望相助隊不應收集不必要個資。audit metadata 只保存稽核必要資料。

若 `originalContent` 包含個資，且收到有效個資或隱私請求，站方可以直接清除 `originalContent`，同時保留非個資 audit metadata。

目前不執行自動七天清空 `originalContent`。保留或清除期限日後再做產品與隱私決策。

## AI 使用邊界

未來可以用人工處理紀錄整理訓練或評測資料，但需遵守：

- 只收明確的「色情廣告」與「濫發廣告」樣本。
- 去除或遮蔽個資與危險外部連結。
- 保留人工理由、覆核結果與資料來源。
- 第一版 AI 只能做候選提示，不得直接刪留言。

## 規章調整

本規章是 MVP 試行版。站方可以依 staging 測試、申訴案例、誤刪率、隊員回饋與隱私風險調整。

任何會擴大權限範圍的變更，例如處理文章、動態本文、帳號或自動刪除，都不屬於本規章小修，必須另行產品決策。
